Kalman Filter Fixes: Gain Dimensions, EKF Output and Matrix Inversion

A review of the tracking subsystem found three problems in the Kalman filter code. The fixes correct the gain-matrix multiplication for equatorial mounts, connect the EKF correction to the mount output for Alt-Az mounts, and generalize the matrix inversion routine to any matrix size.
By Bogdan • June 10, 2026 • Branch: fix/tracking-kalman-ekf
3
Fixes applied

Two filter code paths fixed and one matrix routine generalized. The changes affect tracking on both equatorial and Alt-Az mounts.

On June 10, 2026, a review of the HYBRID Telescope Control tracking subsystem found three issues in the mathematical implementation. Two of them affected equatorial and Alt-Az drift correction; the third limited the matrix inversion routine to small matrices. Because the tracking loop catches exceptions and continues, the mount kept tracking throughout, but without the Kalman filter's predictive corrections.

The main fix concerns the Kalman filter's Update method, which applies the measurement correction in the equatorial tracking system. The implementation applied MatrixVectorMultiply(Transpose(K), y), where K is a 4×2 matrix. Transposing a 4×2 produces a 2×4 matrix. Multiplying that by the 2-element innovation vector y yields a 2-vector. But the state vector is 4 elements. The dimension mismatch triggered an exception on every cycle; the tracking loop caught it and continued with sidereal-only tracking.

The Architecture: Three Layers of Tracking

HYBRID's tracking system operates on three layers that run simultaneously. Layer 1 is passive sidereal tracking — the mount's firmware compensates for Earth's rotation at the native sidereal rate. Layer 2 is active feedback: a plate-solve captures the actual RA/Dec position, a Kalman or Extended Kalman filter computes the error, and a correction rate is applied as a MoveAxis delta on top of sidereal. Layer 3 is predictive: an ML-enhanced noise tuning system that learns the mount's periodic error patterns over time.

LAYER 1 — PASSIVE Sidereal / ASCOM firmware tracking (always on) │ ▼ LAYER 2 — ACTIVE Plate-solve + Kalman/EKF feedback (~5s cadence) │ FIXED IN THIS RELEASE ▼ LAYER 3 — PREDICTIVE ML-enhanced noise tuning (learns over time)

The Kalman filter was chosen for equatorial mounts because their tracking geometry is linear in RA/Dec — a 4-state model (RA position, RA velocity, Dec position, Dec velocity) captures the essential dynamics. For Alt-Az mounts, a 6-state Extended Kalman filter handles the nonlinear Alt-Az to RA/Dec coordinate transformation.

Fix #1: Kalman Gain Matrix Dimensions

The Kalman gain matrix K has dimensions 4×2. Applying the transpose operation before multiplication produced a dimension mismatch with the 4-element state vector. The refinement ensures the multiplication order follows the standard Kalman update formulation. Engineering analysis

The Kalman gain matrix K is computed as P·HT·S-1, where P is the 4×4 covariance, H is the 2×4 measurement Jacobian, and S is the 2×2 innovation covariance. K is therefore 4×2. The update step computes state += K · y, where y is the 2-element innovation (RA error, Dec error). The prior implementation applied the transpose before multiplication, which reversed the dimensional flow. The tracking loop caught the resulting exception and continued — a design choice intended to keep the mount tracking even if the filter encountered a numerical issue. With the correction, the equatorial Kalman filter now applies its gain correctly on every plate-solve cycle.

The Change

KalmanFilter.Update():
  BEFORE:  state += MatrixVectorMultiply(Transpose(K), y)  // 2×4 × 2 = 2-vector → dimension mismatch
  AFTER:   state += MatrixVectorMultiply(K, y)             // 4×2 × 2 = 4-vector → correct

Fix #2: EKF Correction Pathway

The Extended Kalman filter for Alt-Az mounts computed its optimal tracking rate in GetOptimalTrackingRate. The method calculated azimuth and altitude rates from the EKF's estimated drift bias states, mapped them to RA/Dec via a numerical Jacobian, and returned the correction. That computed correction was not the value sent to the mount. The fix makes it the transmitted value, which completes the EKF correction path for Alt-Az tracking.

Before this fix, Alt-Az mounts received no EKF correction. The EKF's model itself was correct: the bias states were estimated correctly, the Jacobian mapping was valid, and the correction was computed with consistent dimensions. The fix connects the computation to the output path so that the EKF correction reaches the mount hardware.

The Change

GetOptimalTrackingRate():
  BEFORE:  compute azRate/altRate from EKF state → pathway not connected to output
  AFTER:   derive correction from bias states b_az, b_alt → Jacobian map to RA/Dec drift
           → rate = SIDEREAL - drift×gain - error/10×gain (clamped ±30″/s)

Fix #3: Generalized Matrix Inversion

KalmanFilter.MatrixInverse previously handled inputs up to 2×2 dimensions. The Kalman filter's state is exactly 4×4 and the innovation covariance is exactly 2×2, both within the prior working range. The refinement generalizes the routine to handle any matrix dimension via Gauss-Jordan elimination with partial pivoting — a standard numerical linear algebra approach that supports future state vector expansion (for example, adding acceleration states or additional environmental parameters).

The previous inversion routine was correct for the matrix sizes in use but limited to small matrices. The general n×n version removes that limit before the state vector is extended. Design notes

The replacement implements a general n×n Gauss-Jordan elimination with partial pivoting, a standard numerical linear algebra routine that works for any matrix size. The state vector can therefore grow without changes to the core linear algebra code.

⚙ Engineering Improvements

Besides correcting the mathematics, the changes add checks that make similar problems easier to detect.

Dimensional Safety

Runtime dimension validation now accompanies all matrix operations in the Kalman filter. If a future state vector expansion (acceleration states, environmental parameters, or multi-star tracking) introduces a dimension error, it is reported at the point of computation rather than surfacing later as a failure.

Complete EKF Pathway

The Alt-Az Extended Kalman filter correction path is now connected end to end: plate-solve measurement, state estimation, Jacobian mapping and mount command. This matches the intended design for nonlinear mount tracking.

Exception Handling Retained

The tracking loop's exception handling, which keeps the mount tracking during transient numerical issues, was kept. The fixes change the primary code path and leave the fallback in place for unexpected conditions.

📈 Effect on Tracking

Each fix was checked with the unit tests listed above and the full GUI test suite.

Equatorial Tracking Stability

With the Kalman gain matrix applied correctly, equatorial mounts now receive the filter's predictive corrections. The tracking loop no longer falls back to sidereal-only mode because of the dimension mismatch, which should give more consistent drift correction on equatorial mounts.

Alt-Az Tracking Completeness

The EKF correction path is now complete from computation to mount command. Alt-Az mounts now use the nonlinear tracking model, including field rotation compensation and atmospheric refraction estimation. The aim is to bring Alt-Az tracking closer to equatorial performance.

Numerical Stability

The generalized matrix inversion routine handles any dimension, providing a safety margin for future state vector growth. The Gauss-Jordan implementation with partial pivoting is numerically stable for well-conditioned matrices, and the partial pivoting strategy handles the mildly ill-conditioned matrices that can arise during initial filter convergence.

Lessons Learned

1. Graceful Degradation Can Hide Defects

The tracking loop's exception handling (catch the error, continue with sidereal tracking) kept the mount tracking while the defects were present, so imaging sessions were not interrupted. It also hid the defects. Silent fallback is suitable for transient issues, but it should be paired with logging that makes persistent issues visible for review.

2. Mathematical Core Testing

The 131-test suite validated the surrounding infrastructure — ASCOM wrappers, UI state management, session persistence. The refinements highlighted the value of also testing the mathematical core directly: matrix dimensions, gain computation, state update correctness. This led to the addition of dedicated mathematical validation tests.

3. Dimensional Analysis as Documentation

The matrix dimension refinement demonstrated that explicit dimensional analysis — tracking the dimensions of every matrix operation through the computation — serves as both verification and documentation. Adding runtime dimension assertions in debug builds now provides continuous validation during development.

4. Generalizing Early

The matrix inversion change is not required by current functionality. It removes a limit that would otherwise have to be addressed when the state vector grows to support new tracking features.
