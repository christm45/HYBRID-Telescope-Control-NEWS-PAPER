Security Audit: Six Fixes Across Four Subsystems

An audit of the voice, camera, mount and web subsystems led to changes in authentication defaults, meridian flip verification, process shutdown, session file writes and FITS handling, delivered in nine commits.

Commits in the audit

A structured audit across four subsystems: voice, camera/imaging, mount/ASCOM/scheduler, and web/MCP/cloud. Each finding was checked against the source code, and each fix was build-tested.

On June 10, 2026, a security audit of four HYBRID Telescope Control subsystems (voice, camera/imaging, mount/ASCOM/scheduler, and web/MCP/cloud) led to changes in six areas of the codebase. Each area was reviewed against the source code, and each finding was confirmed as an actual implementation gap, not a theoretical risk, before it was classified. The fixes were made in nine commits, each verified by a successful build.

Security reviews are a routine part of development, particularly for software that controls physical hardware. This one covered default settings, authentication paths and edge cases.

Hardening — Web Authentication Default

The AuthEnabled default was set for local development convenience. The change enables authentication whenever the web server is exposed beyond localhost, which is standard practice for network-facing services. Engineering principle

The embedded web server's AuthEnabled flag defaulted to false. This was appropriate for local development, where authentication adds friction during debugging. With the change, SetAuthEnabled is activated automatically when an ngrok tunnel is started for remote access, so remote access is not left unauthenticated.

The CORS configuration was also changed. The IsLocalRequest check now treats X-Forwarded-* headers as WAN traffic, so tunneled requests are correctly identified as non-local. The /mcp/* endpoint requires non-local origin plus Bearer token or API key, which adds a second layer of protection for the AI tool interface.

The Change

SetAuthEnabled is now forced ON at both tunnel-start paths (and OFF on stop). The auth gate is scoped to non-local /api/ and /ws/ endpoints. IsLocalRequest now treats X-Forwarded-* headers as WAN traffic. The /mcp/* endpoint requires non-local origin plus Bearer token or API key.

Hardening — Meridian Flip Safety

The scheduler's meridian flip is a safety-relevant operation that rotates the mount 180° as the target crosses the meridian, keeping the telescope on the same side of the pier. The change adds verification: the system now waits for slew completion, verifies that the pier side changed, and halts the session if verification fails.

Prior Implementation

Scheduler calls re-slew to same target. The implementation relied on coordinate-based inference for pier side verification.

New Implementation

Scheduler calls ExecuteMeridianFlipAsync. Waits for slew completion. Verifies pier side changed via ASCOM driver. Halts session on verification failure.

SafeParkAsync was also changed: it now calls Abort + StopTracking before Park, with a StopAllAxes fallback if Park fails. When the ASCOM driver returns "Unknown" for pier side, the flip no longer relies on inference; it halts the session instead, so the mount is not moved on an unverified pier side.

Improvement — Process Lifecycle and Session Persistence

Two changes addressed process management and data integrity. Voice bridge Python processes and the local llama.cpp server now terminate cleanly on app close, with StopLocalLlmServer via taskkill /F /T /PID integrated into the shutdown sequence. These processes therefore no longer keep running after the application exits.

Session state persistence now uses atomic writes. session_state.json, which holds open tabs, todo progress, and conversation history, is written with a lock + atomic temp-then-move pattern: write to a .tmp file, rename on success. A partial write therefore cannot replace the real file, which protects session data if power is lost or the application restarts during a write.

Improvement — FITS Reader Completeness

The FITS reader used by the autofocus pipeline was extended to handle multi-block headers, BZERO/BSCALE scaling, and all BITPIX values. The implementation delegates FITS reading to ImageLoader, which supports these FITS variants. Autofocus measurements are therefore based on correctly scaled pixel data for FITS files from different camera drivers.

Refinement — Process I/O and UI Responsiveness

The tunnel-start operation was changed to prevent UI blocking. The prior implementation used tunnelStartTask.GetAwaiter().GetResult(), which blocked the dispatcher thread. The new implementation uses fire-and-forget Task.Run with async AddMessage on completion, returning "starting..." immediately and reporting the result asynchronously. The zenith azimuth rate was also capped at 5 deg/s to prevent commanding rates that exceed the mount's physical capability at the zenith singularity.

⚙ Engineering Improvements

The audit resulted in the following structural changes.

Secure-by-Default Authentication

Web authentication is now secure by default: the system requires explicit configuration to disable authentication, rather than explicit configuration to enable it. The same default applies to web server features added later.

Meridian Flip Verification

The meridian flip now includes verification of slew completion and pier side, and halts the session on failure. Previously the flip was assumed to succeed; now it is checked, which matters for unattended observatory operation.

Atomic Session Persistence

The lock + atomic temp-then-move pattern for session state is a standard data integrity technique that prevents corruption during concurrent writes or unexpected shutdowns. This pattern can be applied to other configuration files as the system grows.

📈 Operational Impact

Each change affects a specific operating scenario.

Remote Observatory Security

With the authentication and CORS changes, remote observatory operation via ngrok tunnels is authenticated by default. Authentication is enabled automatically when remote access starts, without manual security configuration.

Safety-Critical Operations

The meridian flip changes add verification steps that address a serious failure mode in automated imaging: the telescope approaching the pier. By requiring pier side verification and halting on failure, the system prioritizes physical safety over imaging continuity.

Resource Management

Clean process termination prevents orphaned processes from holding GPU memory and system resources. This matters most for long unattended imaging sessions, where resource leaks could degrade performance over time.
