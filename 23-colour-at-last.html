Imaging Pipeline

Colour at Last: From a Grey Checkerboard to a Colour Master

For years, HYBRID stacked one-shot-colour sessions as a grey mosaic with the sensor’s checkerboard baked into the noise. Giving it colour took a debayering stage, a registration choice that came out of measurement rather than instinct, and the discovery that every colour master the program could write came back garbled. Along the way a 564-frame session asked for 147 GB, and every FITS file turned out to have been counted twice.
By Bogdan • September 30, 2026 • DEV LOG • v1.4.4 PRO

Colour, by the Numbers

1.13–1.80 px on debayered frames against 0.19–0.25 px on the mosaic. The transform is measured on the mosaic and applied to the colour.

A one-shot-colour camera does not record colour. It records a mosaic: a grid of pixels, each sitting behind a single red, green or blue filter, which software must then weave into a colour image. Until this release, HYBRID did not perform that step. A colour session was stacked as a grey Bayer mosaic, the sensor’s two-pixel checkerboard baked into the noise of every frame. The only route to colour was drizzle in CFA mode, and that demands genuinely dithered sub-exposures, which an ordinary imaging session is not.

For software aimed at amateurs, most of whom own a colour camera, that was a large gap. It is closed now, and the way it closed is a short course in why the order of operations matters.

Where Debayering Has to Go

Debayering runs after calibration and before registration, and the reason is the calibration masters. A master dark and a master flat are themselves mosaics: they are per-pixel corrections designed to be applied to raw data. Debayer first and you would be subtracting a mosaic from a smoothed image.

Two reconstructions are offered. Bilinear keeps full resolution and is the default. Superpixel turns each 2×2 Bayer cell into a single pixel — half the width and half the height, and no colour artefacts at all. The mosaic layout is read from each frame’s own BAYERPAT header rather than chosen from a list. The frames of a mono sensor are therefore left untouched whatever the setting, and red and blue cannot be swapped for an entire session by one wrong choice in a drop-down.

Measure on the Mosaic, Apply to the Colour

The obvious design registers the debayered frames. We measured it on a real session before writing it, and the obvious design lost.

registration measured on          RMS residual
debayered colour frames           1.13 - 1.80 px
raw mosaic, then applied          0.19 - 0.25 px

That is five to seven times worse. At a typical image scale, 1.13 to 1.80 px is more than a second of arc of smear put into every frame before integration begins. The cause is interpolation: it hands the star detector broader, flatter peaks, and the centroids pay for it even though the detector finds more stars.

More stars, worse centroids. What interpolation does to a star detector

So registration is measured on the raw mosaic and the resulting transform is applied to the colour frames. On five real frames of NGC 2903 the status bar read 28 stars, RMS 0.24 px, quality 98, in line with the earlier mosaic measurements.

The Colour Files Nobody Could Read

Every FITS writer in the application declared a three-plane cube in the header and then wrote the pixels interleaved, which is not how a FITS cube is stored. Read back by this program or by any other FITS reader, a three-channel master came back as three shredded images.

The defect had never fired, because nothing in the program had ever produced a three-channel file before debayering existed. It would have fired on every colour master. It is fixed in all three writers, and the five-frame colour stack was read back plane by plane by an independent Python script to confirm it: three genuinely distinct channels.

A related fault sat in drizzle. Its mode was pinned to Mono, so drizzling a colour session produced an upscaled grey image with no way to ask for anything else. It now switches to CFA mode on its own when the frames are colour.

147 Gigabytes

With colour working, the next obstacle was arithmetic. A session of 564 frames from an ASI294MC asked for 147 GB of memory, because debayering lived in the whole-frame path and the entire session therefore had to fit in RAM as three-channel images. That is far more than most machines hold, and the application, correctly, refused.

The remedy was to move debayering inside the from-disk banded reader, the same mechanism that had already brought a mono session down from 26 GB to about 1 GB. The same 564 colour frames now stack from disk in about 1.5 GB, and the pixels are identical to those produced by the whole-frame path.

Every File Counted Twice

This one surfaced the first time anyone pressed the STACK button on real frames in the real window — a step that earlier audits had flagged as never having been done. A folder of five FITS lights imported as ten.

On Windows, a three-character search pattern still matches longer extensions: asking for *.fit returns the .fits files as well, a legacy of the old 8.3 short-name rules. The folder scans asked for *.fits and then for *.fit, and for *.tif and then *.tiff, so every frame in the two commonest formats was added twice. Seven places, in five files, did the same thing.

It was not cosmetic. The doubled count fed the frame counter on screen. It fed the memory pre-check, which costed a 564-frame session as 1,128 frames — most of the way to the refusals that send a session down the whole-frame path. And it fed the stack itself, which combined every frame with an exact copy of itself.

That last point matters for rejection. A duplicated pair of identical values narrows the spread that a sigma-rejection step measures, so the thresholds were being computed from data that could not disagree with itself.

A single scanner now answers the question “which image files does this folder hold?” by matching on the extension a file actually has. Eight tests cover it, including one that checks that Windows still behaves this way, so that the explanation in the code cannot quietly become false.

A Stopwatch That Never Started

The same session produced a second finding. After a two-minute stack, the completion dialog announced a processing time of 0.0 seconds. The in-memory stacking route — the one the STACK button uses — was the only path in the engine that never started a stopwatch. Every other path did, which is exactly why no test noticed. The elapsed time is now recorded on every outcome, including a cancelled or failed run.

The GPU, for the First Time

The release also records an unglamorous victory. GPU acceleration had never actually worked: a missing assembly binding made every GPU stack fail and fall back to the CPU, so the GPU option never accelerated anything. It now runs. The normalisation pre-pass shows its progress, every stack is written to the log, and when the from-disk route is declined, the reason is shown in the released build rather than only in a debug window.

What Remains

Superpixel debayering still forces the whole-frame path, because it halves the frame and a band of the output is not a band of the input. Colour balance is not applied: raw one-shot-colour frames are not white-balanced, and a yellow star really does record more blue than red through a typical sensor, so that belongs to post-processing. Local per-tile normalisation still forces the whole-frame path, spectrophotometric colour calibration remains disabled, and two-pass registration with automatic reference-frame selection is still not implemented.

What Changed

Debayering after calibration and before registration, bilinear or superpixel, with the pattern read from each frame’s own header. Registration measured on the mosaic. Three FITS writers repaired. Drizzle switches to CFA by itself. Debayering moved into the banded reader. One folder scanner. A stopwatch that starts. GPU stacking that works.

What Didn’t

Mono sessions. The stacking mathematics, the rejection methods and the banded reader’s pixels are untouched, and a mono sensor’s frames pass through the debayer stage unchanged.

The pipeline was never short of algorithms. It was short of the plain mechanics that sit around them: a header written in the wrong order, a search pattern that quietly matches too much, a timer that nobody started. Most of this release was found not by thinking harder about stacking but by clicking the button.
