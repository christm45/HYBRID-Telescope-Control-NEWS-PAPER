Cameras

Canon EOS 550D Bench Test: Imaging Sequence and RAW Capture Fixes

With a Canon EOS 550D connected to a PC, Start Imaging Sequence finished in 25 milliseconds and reported success without taking a picture. Version 1.4.7 PRO fixes that defect and several others found in the same test session, all of which required a real camera to reproduce: wrong RAW quality code, a fixed download timeout, an SDK decoding failure and a recovery dialog that closed the application.
By Bogdan • October 5, 2026 • DEV LOG • v1.4.7 PRO

Sequence Duration

25 ms
duration of a sequence that captured nothing and reported success

Frames captured: 0. Duration: 00:00:00. Average time per frame: 0.0 s.

The test setup was a Canon EOS 550D, a body commonly used in astrophotography, connected to a PC by USB. No mount was connected and, since the test was run in daytime, there was no sky. This isolates the camera and the software from every other component.

The camera was connected, recognised and configured from the sensor database — 5184×3456 pixels, 4.3 µm. Test capture, live view, and changes of shutter speed and ISO all worked. Start Imaging Sequence was then pressed.

After 25 milliseconds the program reported that the sequence had completed successfully. No exposure had been taken.

Debug Output

Neither the activity log nor the window showed any error. A listener was attached to the program’s debug output and the sequence was run again. The engine output was:

[ImagingSequence] Filter switch to 'L' (pos -1) FAILED - frame 1 skipped.
[ImagingSequence] Filter switch to 'L' (pos -1) FAILED - frame 2 skipped.
[ImagingSequence] Filter switch to 'L' (pos -1) FAILED - frame 3 skipped.
[ImagingSequence] Sequence complete! 0 frames captured

Implicit Filter Entry

A sequence without a per-filter plan runs on an implicit entry named “L”, position −1. The engine sent that entry to the filter wheel like any other. With no wheel connected — the case for every DSLR and most ASI setups — the window’s handler returns false. The engine does not expose a frame through a filter it could not select, since the file would be labelled with the wrong filter, so it skipped the frame.

A second defect followed. The engine stops a run after five consecutive failed frames. The test requested three frames, so three skips stayed under the limit, the loop reached its end, and the result was Success: true, 0 frames.

Both are fixed. The engine now uses the filter wheel only when a filter plan exists, and a run that captured no frames is reported as failed, with its reason.

Skipped frames were not counted as failures of the run, so a sequence with zero frames was reported as successful. On the sequence-completion check

Camera Without a Mount

The next run also stopped immediately, for a different reason. With no mount connected, the meridian-flip check returned unknown, and the engine treats unknown as a reason to abort “to protect the telescope”. With only a camera connected, there is no telescope to protect. Now a mount that was never connected means no flip is needed; only a mount that was connected and then lost is treated as unknown.

That abort was also not displayed. The engine reported its end to the window only through its normal exit path; an exception, a validation error or a cancellation inside a capture returned a failed result that the caller did not check. The screen showed nothing and the Start button stayed disabled. Every exit path now reports to the window.

RAW Requests Returned JPEG

Once the sequence ran, the files returned were JPEG. The program requests RAW by setting an image-quality code, and the code was wrong: 0x00640F0F instead of 0x0064FF0F, the value in Canon’s own SDK header. The camera rejected the setting, the rejection was ignored, and a RAW request always produced a JPEG. The code is corrected, and a rejected setting is now logged.

73 Seconds for a 35-Second Exposure

A 35-second bulb exposure took 73 seconds to download. The most likely cause is the camera’s long-exposure noise reduction: after a long exposure, the 550D can record a dark frame of the same length before sending the image.

The program waited a fixed 60 seconds for the image, so any exposure longer than about a minute would have lost its picture. The wait now scales with the exposure, and the estimated sequence duration includes the dark frame: 35 seconds is estimated at about 80 rather than 45, against the 73 measured. With noise reduction disabled on the body, the estimate is slightly high, which is the safer direction.

RAW Decoding Fallback

For focus measurement and plate solving, the program must read the camera’s RAW file. Canon’s SDK rejected every attempt to develop the 550D’s file at full size — error 7, not supported, in every output format tried — while decoding the 160×120 thumbnail without error. The cause was not determined.

Every Canon RAW file also contains a full-size JPEG preview. The program now falls back to that preview: eight bits instead of fourteen, which is sufficient for a focus metric or a plate solve.

Recovery Dialog Closed the Application

One defect was unrelated to cameras. After a forced close, the next start shows Interrupted Session Detected. Pressing either Resume or Start Fresh then closed the whole application.

The cause is a framework rule. The application is configured to exit when its main window closes, and the first window created is treated as the main window. The recovery dialog was created first, so closing it ended the program. The dialog is now managed explicitly and is no longer treated as the main window once it has returned its answer.

Minor Fixes

The live view on the Tracking tab was paced by the shutter speed, giving 0.8 images a second at a one-second exposure, whereas the camera’s own stream delivers about six. It was labelled as an ASCOM camera, and its footer kept showing the camera name after Disconnect. The Cancel button of the camera-type chooser was cut off at the bottom of its window. All four are fixed.

Not Tested

There were no stars in the test images. The frame-quality scorer gives a score of zero to an image without stars, so it requested each frame twice; and the debug build used for the test has no embedded Python, which the scorer requires. A test under a real sky, with a focuser and a mount, is still pending. The 500D, 600D and 700D bodies are untested, and the installer has not yet been run on a clean machine.

What Changed

The filter wheel is used only when a filter plan exists. A run with no frames is reported as failed. No mount means no flip is required. Every exit path of the engine reports. RAW requests return RAW. The download wait scales with exposure and the estimate includes the dark frame. JPEG preview fallback when the SDK cannot develop the RAW. The recovery dialog no longer closes the program.

What Didn’t

A sequence that has a real filter plan still skips a frame when its wheel fails, and stacking results are unchanged. The new engine tests fail on the old code and pass on the new, and the full test suites pass.

Automated tests did not detect that the sequence button produced no exposures, or that the camera was being sent the wrong image-quality code. A real camera connected to the PC reproduced both within the first test session.
