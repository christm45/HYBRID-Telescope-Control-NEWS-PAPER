Audit

October Audit, Part 1: Scheduler, Locale and Stacking Fixes

Results of a full review of the program’s interface and code by six independent reviewers. Most high-severity findings were not crashes but buttons that reported success without performing their action, and settings that were ignored. This part covers the scheduler, comma-decimal parsing, the pier-side rule, GPU stacking and the remote-access tunnel.
By Bogdan • October 25, 2026 • DEV LOG • after v1.4.11 PRO

The Audit in Numbers

~25
high-severity findings, each checked against the code

Six reviewers each took one part of the program: the interface wiring, the mount and tracking, the cameras and sequences, stacking, the web and voice services, and the rest of the interface. All test suites passed before the audit started, which shows that these defects were outside what the tests covered.

The audit covered the whole program, interface and code, with the aim of reporting anything that did not work. Before it began, all test suites passed: 1,016 interface tests and 574 image-processing tests. None of the defects below was detected by them, because almost none raises an error; the affected functions report success.

Scheduler Used the Guide Camera

The Target Scheduler was given the program’s first camera object, which is the guide and plate-solve camera. With a native ZWO or Canon imaging camera, every target failed with “camera not connected”. With an ASCOM guide camera, the light frames were taken through the guide scope. The scheduler also always used bin 1, and a second run on the same evening overwrote the first run’s frames, because the default file name contained no time. The scheduler now uses the imaging camera, applies the configured binning, and does not overwrite existing frames.

Three Buttons That Did Not Perform Their Action

Apply to Sequence showed “Target schedule applied to imaging sequence!” without reading any targets. RUN PLAN asked for confirmation that “the scheduler will start immediately and run unattended”, then only stored the plan and logged that it was ready. The Night Plan window could not display any plan: one drawing element was added to two parents, which WPF does not allow, so every non-empty plan ended with “Plan generation failed”. An empty schedule was replaced, without notice, by five sample Messier targets.

Apply now passes the schedule to the scheduler queue. RUN PLAN opens the scheduler with the plan’s targets and starts it, after passing it the observing site; an independent review of the fix found that the site was still missing in the first version. The sample targets have been removed.

Each of these buttons displayed a success message without checking that the action had been carried out. On the dialog that applied a schedule it had not read

Comma Decimal Separator: “31,94” Seconds

Windows configured for Serbia, France or Germany uses a comma as the decimal separator. The scheduler parsed right ascension with a parser that treats a comma as a thousands separator, so 05:34:31,94 became 3,194 seconds — and that value was used as the slew target. The same type of defect set a pixel size of “4,63” in the equipment profile to zero while the dialog reported “saved”, sent “1,23” to the quality analyser’s Python, and built the Gaia query for colour calibration as CIRCLE(’ICRS’, 123,45, 41,27, 2), which Gaia rejects. On Windows with comma decimals, colour calibration therefore always reported “0 catalogue stars”. All of these now accept either separator, and every number sent to another program is written with a point.

Pier-Side Fallback Rule, Measured

When a mount cannot report which side of the pier it will use, the program falls back to a rule: past the meridian and still on the pre-flip side, the flip is due. The rule checked the wrong side. The convention was measured on the ASCOM simulator: two hours east of the meridian it reports pierWest, two hours west it reports pierEast. The old rule returned “not due” while the telescope tracked towards the pier, and “due” again right after a correct flip. It now uses the measured convention. The same test confirmed that the declination-axis sign used by the tracking loop was already correct.

Stacking: GPU Option Disabled Other Settings

The “GPU acceleration” option is enabled by default. The GPU path implements only the final combination step, so with it enabled the program skipped drizzle, normalisation, quality weighting and automatic rejection without notice, computed “Sum” as a mean, and for median and sigma-clipping used only the first 256 frames — while reporting every frame as accepted. Settings the GPU path cannot handle are now processed on the CPU instead. Local normalisation had a separate fault: in a tile of empty sky it fitted a slope to noise and clamped it to 0.1, scaling each frame’s data down by a factor of two to ten. It now matches each tile by median and spread.

Remote-Access Tunnel and Empty Credentials

The remote-access tunnel wrote a log line for every connection into a pipe that was never read; once the pipe was full, the tunnel stopped working while still reporting itself as running. The pipe is now read, and the tunnel, like the MCP server, is closed with the program, including after a crash. A damaged settings file could also leave the web credentials empty, and an empty user name and password then matched each other. Empty credentials are now never accepted; they are regenerated and saved, and the settings file is written atomically.

Testing

Each fix has a test that fails on the old code and passes on the new, and each test was confirmed to fail on the old code: 22 tests for this first group. A second, independent review of the fixes alone found four mistakes in them — among them the missing site, Canon RAW files that would have been renamed .fits, and two scheduler sessions able to run at once — all corrected before the commit. The full suites pass, including 18 tests on 564 real NGC 2903 frames.

What Changed

The scheduler uses the imaging camera. Apply and RUN PLAN perform their stated actions. Comma decimals are parsed correctly. The fallback flip rule matches the measured pier sides. The GPU path no longer drops settings. The tunnel no longer stalls, and empty credentials are rejected.

What Didn’t

None of this has been tested under a real sky yet. These fixes are in the source and will ship in the next installer; v1.4.11, currently available, does not contain them.

A crash is reported immediately. A button that reports success without acting may go unnoticed until it is used during an observing session. This audit was intended to find such cases beforehand.
